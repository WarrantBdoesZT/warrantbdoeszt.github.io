💡 Why I Built This

You assume an attacker already has a foothold. The question isn't if they got in — it's how far can they go before something stops them. ZTAuditor answers that by probing outward from where it runs and comparing what it can actually reach against what your segmentation policy says should be reachable.

The unit of analysis is a path — source zone → target endpoint : port — because a segmentation flaw is never a property of a host on its own. The same SMB port is a designed admin route from your management VLAN and a domain-compromise path from a guest VLAN.

The distinction most tools miss

A failed connection has three meanings, and collapsing them makes the results worthless:

Wire behaviourVerdictWhat it tells you
SYN/ACKOpenA service is listening and the path is open
RSTClosedThe host answered — packets reach it, nothing is filtering
dropped / ICMPFilteredA boundary control is enforcing
no answer possibleUnknownNothing can be concluded — never counted as a pass

Closed is the one people miss. Nothing is exposed today, but nothing is blocking either — the moment that service is installed, the path is open. That's the difference between being segmented and being lucky. A tool that reports only a boolean cannot tell a working firewall from a powered-off host.

What it is NOT:

  • Does not exploit vulnerabilities
  • Does not capture credentials
  • Does not make any changes to the environment
  • Does not require Domain Admin — the segmentation engine needs no credentials at all

The probe engine is unauthenticated. The optional enrichment checks read Active Directory and host configuration with a standard domain user, and explain why a reachable path is worse than it looks — but if they can't run, the segmentation assessment still completes.

📘 How to Use

1 · Prerequisites

  • Windows 10 1809+ or Server 2019+
  • Nothing else to install — the download is self-contained; .NET is bundled
  • Written authorisation to scan the target network

Optional, and only for the enrichment checks that add host context:

  • A standard Domain User account — no Domain Admin rights
  • Remote Registry running on target hosts (deploy via GPO)

The .NET 8 SDK is only needed if you build from source rather than using the download.

2 · Describe your network

Segment boundaries come from a zone map you declare, not from guessing at IP addresses. Two templates ship in the zip:

copy zones.example.json  zones.json    # CIDR → zone, trust tier, role
copy policy.example.json policy.json   # which cross-zone flows are approved

zones.json maps CIDRs to zones with a trust tier (0 = control plane … 4 = untrusted). Matching is longest-prefix, so a tier-0 /24 correctly beats the /8 containing it.

policy.json declares which cross-zone flows are approved, default-deny, each with an owner and an expiry. Without it every legitimate admin path is reported as a violation and triage stays manual forever.

If zones.json is absent, cross-zone analysis is skipped and said so rather than guessed at. Producing no findings is honest; producing confidently wrong ones is not.

3 · Run it

Always start with a dry run — it prints the full probe plan without sending a packet:

# See exactly what would be probed. No traffic.
.\ZeroTrustAuditor.exe --hosts-file .\targets.txt --domain corp.local --dry-run

# Then a real run, paced
.\ZeroTrustAuditor.exe --hosts-file .\targets.txt --domain corp.local --rate 50

Scope and output:

FlagDescription
--hosts h1,h2Comma-separated list of hostnames
--hosts-file file.txtPath to text file with one hostname per line
--domain corp.localActive Directory domain FQDN (required)
--output ./reportsOutput directory (default: ./reports)
--skip-modules A,BSkip modules: AdAuditor, ProtocolProbe, LateralPathAnalyzer, ShareAuditor, SegmentationChecker

Segmentation:

FlagDescription
--zones zones.jsonZone map: CIDR → zone, trust tier, role
--policy policy.jsonApproved cross-zone flows (default-deny)
--services services.jsonHigh-risk service catalog

Probe safety:

FlagDescription
--dry-runPlan every probe and send nothing
--rate 100Probes per second (0 = unlimited)
--max-concurrency 128Ceiling on simultaneous probes
--allow-ot-probingOff by default. OT/ICS protocols (Modbus, S7, DNP3, EtherNet/IP, BACnet) are never actively probed — an unexpected TCP connect can fault a controller. Also requires activeProbing on the zone.

4 · Read the output

The main deliverable is segmentation-TIMESTAMP.html:

SectionAnswers
Zone matrixIs the network actually segmented? Source zones on rows, worst outcome per pair. Grey means not assessed — which is not the same as clean.
Exposure registerWhich endpoints allow high-risk ports, from where, sorted by severity then blast radius
ViolationsReachable paths policy doesn't permit, each with the exact firewall change
ZTMM scorecardCISA Networks-pillar maturity, scored only from what was measured
Enforcement evidenceThe boundaries that do block — what not to regress

Alongside it: exposure-register-*.csv for ticketing, reachability-*.json with every raw probe outcome, and the legacy audit-* host findings in HTML, JSON, CSV, Splunk HEC, Sentinel and CEF.

Findings are classified by comparing observed reachability against declared policy:

ObservedPolicyStatus
OpendenyViolation — the headline finding
CloseddenyUnenforced — nothing listening, nothing blocking
FiltereddenyEnforced — the control works
FilteredallowDrift — an approved path is broken
OpenallowCompliant — working as designed

Severity comes from the zone pair, not the port. SMB from the management VLAN to an app server is the designed admin path and scores low; the identical SMB from a guest VLAN to a domain controller is Critical.

SeverityScoreRecommended SLA
Critical9.024–48 hours
High7.07 days
Medium5.030 days
Low3.090 days

Host weaknesses escalate the paths they make worse: a reachable 445 with SMB signing disabled, on a host whose local admin password is shared across the estate, is a different finding from a reachable 445 alone.

5 · Cover the rest of the network

One run measures reachability from one source zone — one row of the matrix. Run from a host in each zone and merge:

.\ZeroTrustAuditor.exe merge .\user\reachability-*.json .\dmz\reachability-*.json ^
    --zones zones.json --policy policy.json --report

No agents, no deployed infrastructure. Merging doesn't invent coverage: unmeasured pairs stay not assessed, are excluded from the maturity score, and disagreements between runs are recorded rather than smoothed over.

⚠️ Before you run it

An internal port sweep is an intrusive act even when read-only and authorised. Get written authorisation from the system owner first.

Start with --dry-run and confirm the zone attribution looks right — especially that the audit host resolves to the zone you expect, since every finding is relative to that. Then a small host list at a low rate before anything wide.

OT and ICS protocols are never actively probed unless you explicitly opt in on both the command line and the zone. Leave it that way unless you have written approval from the OT owner.
